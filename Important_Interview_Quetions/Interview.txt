To get you started, here are the answers to the 10 highest-probability interview questions.
1. What is FAISS?

Answer:

FAISS (Facebook AI Similarity Search) is an open-source library developed by Meta for efficient similarity search and clustering of dense vector embeddings. In RAG applications, FAISS stores document embeddings and retrieves the most semantically similar documents for a user's query.

Example:

Store embeddings of PDF chunks.
Convert the user's question into an embedding.
Search for the nearest vectors.
Return the relevant chunks to the LLM.
2. Why is FAISS used in RAG?

Answer:

Large Language Models cannot search thousands of document chunks efficiently. FAISS enables fast semantic retrieval by storing embeddings and performing nearest-neighbor search.

Without FAISS:

Scan every document.
Slow retrieval.

With FAISS:

Millisecond retrieval.
Scales to millions of vectors.
3. What is ChromaDB?

Answer:

ChromaDB is an open-source vector database designed for AI applications. It stores:

Embeddings
Original documents
Metadata

Unlike FAISS, Chroma also supports persistence and metadata filtering, making it suitable for end-to-end RAG systems.

4. Difference between FAISS and ChromaDB?
FAISS	ChromaDB
Vector search library	Vector database
Stores embeddings	Stores embeddings, documents, metadata
Metadata filtering is limited	Built-in metadata filtering
Manual persistence	Built-in persistence
Extremely fast search	Slightly more features

Interview Tip: Mention that Chroma often uses FAISS or similar indexing techniques internally for search, but provides a higher-level database interface.

5. What is an embedding?

Answer:

An embedding is a numerical vector representation of text, images, or other data that captures semantic meaning.

Example:

"Artificial Intelligence"

↓

[0.23, -0.91, 0.55, ...]

Documents with similar meanings produce embeddings that are close together in vector space.

6. What is vector search?

Answer:

Vector search compares the embedding of a query with stored embeddings and retrieves the most similar ones based on a similarity metric such as cosine similarity or Euclidean distance.

Unlike keyword search, vector search understands meaning rather than exact words.

7. What is similarity search?

Answer:

Similarity search finds items whose embeddings are closest to the query embedding.

For example:

Query:

How do AI agents work?

Documents:

AI Agent Architecture
Machine Learning Basics
Cooking Recipes

The AI Agent document has the highest similarity score and is returned.

8. What are metadata and metadata filtering?

Answer:

Metadata is additional information associated with a document.

Example:

{
  "source": "Azure.pdf",
  "page": 12,
  "author": "Microsoft"
}

Metadata filtering allows retrieval from only selected documents.

Example:

filter={"source":"Azure.pdf"}

This is useful when users want answers from a specific document or category.

9. Explain the RAG pipeline.

Answer:

A Retrieval-Augmented Generation (RAG) system combines document retrieval with an LLM.

Pipeline:

Documents
     │
     ▼
Load Documents
     │
     ▼
Split into Chunks
     │
     ▼
Generate Embeddings
     │
     ▼
Store in Vector Database
     │
───────────────
User Question
     │
     ▼
Generate Query Embedding
     │
     ▼
Similarity Search
     │
     ▼
Retrieve Relevant Chunks
     │
     ▼
Send Context + Question to LLM
     │
     ▼
Generate Answer
10. How would you improve retrieval quality?

Answer:

Several techniques can improve retrieval quality:

Choose a high-quality embedding model.
Optimize chunk size and chunk overlap.
Use metadata filtering.
Increase or tune the number of retrieved documents (top-k).
Apply reranking models after retrieval.
Remove duplicate or noisy chunks.
Keep the vector database updated with fresh content.
Use hybrid search (keyword + vector search) when appropriate.
Example Interview Follow-up

Interviewer: Why not just search the PDF using keywords instead of FAISS?

Strong Answer:

Keyword search relies on exact word matches. If the document says "automobile" and the user searches for "car," keyword search may miss it. FAISS performs semantic search using embeddings, so it understands that "car" and "automobile" are closely related and can retrieve the relevant document even when the wording differs.
